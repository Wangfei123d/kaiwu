# UI 设计准则

为开物设计或修改界面时，遵循以下要求：

## 界面表达

- 界面尽可能简洁，优先保留完成任务必需的内容和操作。
- 尽量减少提示性、解释性和重复性文本。用清楚的层级、图标和状态表达代替长说明；必要说明保持简短，并放在用户需要时才出现的位置。
- 延续当前页面和开物的设计系统。复用已有颜色、字体、间距、边框、圆角和组件，不为单个界面另造一套视觉语言。
- 避免无意义的装饰、嵌套卡片和多余分隔线。保持留白，让主要内容和首要操作清楚可见。
- 让窄面板和小窗口仍可读、可操作；优先使用弹性布局，避免固定宽度造成截断或横向溢出。

## 操作与图标

- 常见动作优先采用一致的矢量图标（优先使用项目已有图标或内联 SVG），尽量减少纯文本按钮。
- 仅图标按钮必须提供可访问名称，并在需要时提供简短悬停提示；保留键盘焦点样式。
- 对不常见、含义不明确或结果不可逆的操作，使用清楚的文字标签，不要为了减少文字牺牲可理解性。
- 每个界面突出一个主要操作；次要动作使用低对比度或收纳到合适的菜单中。
- 控件要有清晰的默认、悬停、按下、选中、禁用和键盘焦点状态。

## 动效

- 加入克制、简洁且细腻的动效，帮助用户理解状态变化和操作反馈。
- 优先使用透明度、轻微位移、缩放和颜色过渡；速度响应迅速，缓动自然，不让动效拖慢操作。
- 只动画有意义的变化，避免持续闪烁、无目的循环、过度错开或大范围弹跳。
- 对展开、收起、切换、悬停和成功反馈使用相互协调的动效节奏。
- 尊重 `prefers-reduced-motion`，为减少动态效果的系统设置提供静态或弱动效表现。

## 交付界面前

- 检查文本是否可以再精简、按钮是否可以用合适的图标表达、是否存在重复容器或多余装饰。
- 检查图标按钮名称、键盘焦点、颜色对比、窄屏布局和减少动态效果状态。
- HTML 预览应具备真实交互反馈；不要放置看似可点击但没有行为的控件。
