# 完善节点全区域拖动

## 操作背景

用户反馈节点只有标题比较容易拖动，要求按住节点内任意内容区域都能移动节点。

## 原因与操作过程

1. 检查 `plugins/drama/index.js` 的 `bindNodeGestures`：起手判定将正文、生成结果、技能面板、图片输入等完整容器排除，导致它们的子元素也不能拖动。
2. 在隔离浏览器加载真实画布插件，拖动文本正文后节点坐标仍是原位置，复现失败。
3. 将内容和按钮区域纳入待判定手势。移动超过现有 4 像素阈值后才捕获指针、移动选中节点组；普通单击仍交给输入框、按钮及预览面板。
4. 对实际拖动产生的点击进行拦截，避免移动导入按钮时弹出文件选择窗口，或移动预览标签时切换模式。
5. 临时跟踪文档指针事件，保证快速划出节点仍能继续拖动。窗口失焦、指针取消或捕获丢失时清理手势并恢复起始坐标。
6. 拖动时显示抓取光标；文字区域按 Shift 拖动可使用原生选字。端口连线和节点边缘拉伸继续使用独立手势。

## 涉及的知识点

- 移动阈值：鼠标按下之后移动几像素才算拖动，避免普通点击被识别为拖动。
- 指针捕获：拖动开始后，即使鼠标离开节点，节点仍能接收移动事件。
- 点击拦截：拖动按钮与单击按钮是两个动作，拖动完成时不能顺便执行按钮。
- 手势取消：窗口失去焦点等情况下，需要释放跟踪和光标样式，避免下一次点击受到影响。

## 分析过程

问题来自过大的排除范围。修复保留既有的吸附、缩放换算和多选组移动逻辑，只调整手势从哪里开始以及如何区分点击、拖动和选字。验证使用内存项目夹具，未读取用户短剧项目或请求模型。

## 验证结果

- `node tools/check-node-drag.cjs`：修复前文本正文拖动断言失败；修复后正文、Markdown、图片、按钮、技能面板、输入框、Shift 选字、快速离开节点、取消手势、多选组、端口和拉伸检查通过。
- `node tools/check-text-node-layout.cjs`：正文与编辑框自适应、滚动、尺寸调整、编辑保存和导入确认检查通过。
- 吸附、框选、拉伸、连线和生成输出面板的 23 项相关测试通过。
- 修改后的 JavaScript 语法与差异空白检查通过。
