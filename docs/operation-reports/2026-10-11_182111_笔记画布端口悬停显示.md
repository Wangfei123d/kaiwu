# 笔记画布连接端口按距离显现

## 操作背景
用户在 HTML 预览中选择了 B「节点预落位/最近端口显现」方案：四个连接端口默认隐藏，鼠标靠近某一侧时只显示最近的一个；正在连接的起点需保持可见。

## 操作过程
### 步骤一：确认原有行为
- 做了什么：检查笔记画布端口样式和鼠标事件处理。
- 结果：原样式在节点悬停或选中时会同时点亮全部端口，鼠标移动处理又会在没有拖动手势时提前返回，因此无法做邻近提示。

### 步骤二：实现 B 方案
- 做了什么：加入最近端口距离判断（54 屏幕像素）、隐藏时禁用鼠标命中、显现时淡入缩放，并在离开画布时清理提示状态；端口被其它节点遮住时不作为候选。连接中的起点和键盘聚焦端口仍显示。
- 结果：完成；只改动笔记画布端口交互与对应样式。

### 步骤三：运行检查
- 做了什么：新增端口悬停规则检查，运行端口、画布数据和保存会话相关的聚焦测试，并执行 JavaScript 语法检查。
- 结果：16 项测试通过，语法检查通过。

### 步骤四：启动并目视确认
- 做了什么：启动 E:\project\kaiwu 中的开物，检查笔记画布窗口与状态。
- 结果：开物成功打开；启动日志显示笔记库 E:\仓库可用、笔记画布已登记、9 个插件加载且 0 个失败。窗口截图确认鼠标附近仅出现一个连接端口，其他端口隐藏；画布状态为“已保存”。

## 涉及的知识点
- CSS 透明不等于不可交互：隐藏端口还要关闭 pointer-events，避免挡住节点拖动。
- 最近点判断：比较鼠标与四个端口中心的屏幕坐标距离，跨缩放级别仍保持稳定的视觉触发范围。
- 节点遮挡：用屏幕命中检查排除被上层节点盖住的端口。

## 分析过程
### 遇到的问题
所有端口常亮且无法基于鼠标位置只显示最近端口；若仅设透明，端口仍可能接收指针，干扰节点拖动。

### 排查思路
分别追踪样式显隐规则、无手势时的 pointermove 早退，以及拖线完成时的 elementFromPoint 命中方式。

### 解决方案
保留端口按钮和现有拖线流程，只增加邻近状态类；让隐藏端口不参与鼠标命中，只有附近端口和连接起点可命中。这样保留旧连接方式，不必改画布数据或拖线模型。

## 注意事项
- 连接端口现在需要鼠标靠近才会显示；键盘聚焦或正在连接的起点仍可见。
- 本次未改动画布内容，也未保存或删除节点。
- 自动化测试检查了样式与事件接线；实际界面另外做了启动后的目视确认。
