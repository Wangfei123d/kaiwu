# 开物工具移入“窗口”菜单并重启

## 操作背景

用户确认移除顶部“工具”入口和工具侧栏，将六个可用工具集中放入原生“窗口 → 工具”子菜单，并在修改完成后重启开物。

## 操作过程

### 步骤一：实现工具与普通面板分组
- 做了什么：工作台根据注册信息和已登记视图拆分普通面板、工具面板；工具使用既有 `tool:<pluginId>:<id>` 标识，并从普通面板列表去重。
- 结果：完成；相关状态表测试通过。

### 步骤二：传递并构建原生窗口菜单
- 做了什么：主进程只接收白名单纯数据；原生“窗口”菜单将工具放进“工具”子菜单，普通面板继续保留原菜单项及三态行为。
- 结果：完成；菜单与载荷测试通过。

### 步骤三：移除旧工具视图
- 做了什么：删除顶部工具入口、工具侧栏和共享内容区装配；复用工作台的受校验打开逻辑，使新开的工具面板聚焦，并在设置页触发时返回笔记工作台。
- 结果：完成；页面契约测试通过。

### 步骤四：自动化验证
- 做了什么：运行 JS 语法检查、四个相关测试文件、全量 `npm test`、`npm run selftest`、`npm run selftest:acceptance` 和本次文件范围内的 `git diff --check`。
- 结果：语法检查与 20 项定向测试通过；全量测试 2078 通过、0 失败、1 跳过。两个 Electron 自测都运行到旧 Markdown 编辑器断言时失败，共 9 项：自测寻找旧编辑块 DOM，但当前界面输出 `.md-live-editor`；在失败前，启动、插件注册、工具未自动打开等相关检查通过。

### 步骤五：启动并核验进程
- 做了什么：确认开始时无开物进程后执行 `npm start`，并检查 Electron 主进程及渲染进程。
- 结果：成功；启动日志报告普通面板 8 项、工具 6 项，插件 `activated=9`、`broken=0`；主进程和渲染进程保持运行。

## 涉及的知识点
- Electron 原生菜单：主进程负责构建“窗口 → 工具”层级，并通过已有 IPC 回调打开工作台视图。
- 工具面板 ID：以 `tool:<pluginId>:<id>` 作为稳定标识，方便布局树与菜单状态对应。
- IPC 白名单：只传递菜单需要的 ID、标题、打开状态和活动状态，不让渲染层传入任意行为对象。
- Electron 进程结构：一个主进程管理 GPU、utility 与 renderer 子进程；重启后检查主进程和 renderer 存活。

## 分析过程

### 遇到的问题
应用级自测在 Markdown 编辑器部分报告 9 项断言失败，自测期待旧编辑块结构，但运行页面使用实时 Markdown 编辑器结构。

### 排查思路
用完整启动日志确认插件加载正常且没有未捕获异常；将失败限定到编辑器 DOM 断言；另以菜单结构、工具状态表、IPC 净化和主界面移除契约的定向测试验证本次改动。

### 解决方案
保留本次已通过的范围内实现，不扩大到修复无关的 Markdown 自测断言；在结果中明确披露该自测限制。
