# 面板分隔条往返拖动抖动复查

## 背景与原因

用户反馈上次关闭拖动过渡的修正未生效。旧窗口的自定义菜单调用 `Menu.setApplicationMenu(null)`，没有注册 Ctrl+R；上轮仅发送快捷键，实际没有重新加载代码。

侧栏使用 220 毫秒 flex 过渡。拖动每次改动宽度后，过渡会追赶新的目标，快速反向时导致边缘落后、跳动。当前修正使用工作台上的 `pw-resizing` 状态，在拖动期间关闭侧栏过渡，松手或取消后恢复。

## 操作与验证

1. 读取用户录屏，用本地 ffmpeg 抽帧确认三栏布局和往返拖动现象。
2. 在独立数据目录启动完整应用，使用相同布局，通过 Electron 原生鼠标输入和每帧几何读数做对照。没有调用用户的模型或修改用户的笔记、日程。
3. 同样的 160 个采样下，恢复旧过渡的最大跟随偏差为 147.5 CSS 像素；当前修正为 0.075 CSS 像素。
4. 新增 `tests/panel-workspace-resize-renderer.cjs` 和 HTML 夹具，覆盖左右边缘、上下分割、未拖动分隔线的位置、拖动结束清理和每次只保存一次布局。480 个采样通过，最大偏差小于 0.1 CSS 像素。
5. 补全旧 DOM 替身缺少的 classList.toggle、removeAttribute，并将过时的尺寸角标期望与已批准的“移除面板大小”保持一致。`node --test tests/panel-workspace.test.js`：39 通过、0 失败。
6. 使用 Windows 窗口操作退出旧窗口，确认窗口列表中已不存在开物，再通过已安装的 Electron 运行时启动当前工作树：`C:\Users\18014\.codex\worktrees\52a5\kaiwu`。
7. 新窗口 ID 为 201770，启动进程 PID 为 48292。在实际窗口将分隔条向右、向左、再向右拖动，确认边缘与指针终点一致，并恢复检查前的面板宽度。

## 知识点与后续操作

- 动画会让尺寸逐渐接近目标；直接拖动时应立即跟随指针，避免反复改变动画目标。
- 假 DOM 不能运行 CSS 动画，因此还需要真实浏览器测量每帧位置。
- Electron 自定义菜单移除原生菜单后，Ctrl+R 不一定有效。后续任务应关闭旧进程后从明确的工作树路径启动，并检查新窗口，而不能将快捷键发送成功当成重载成功。
- 报告保存在工作树的 `docs/operation-reports` 内，遵守本次文件系统可写范围。
