# 按需求启用技能

## 使用方法

1. 新建“技能”节点，点节点进入编辑，填写名称、适用需求、适用场景和排除条件。
2. 在技能正文里填写说明，或把文本 / 剧本、文本生成节点连入技能的“文本”端口。支持多个来源，运行时保留全文。
3. 如需参考图，新建“图片输入”节点并导入 PNG/JPEG/WebP；也可以使用已有画面生成结果。将图集输出接入技能的“图集”端口。
4. 把技能输出连入文本生成或画面生成节点的“技能”端口。一个接收端可以连入多个技能。
5. 在接收端提示词中直接描述需求，然后运行接收端。不需要写 `@`、技能名称或固定引用语法。

例如，技能用途填写“保持主角在不同镜头中的长相、发型和服装一致”，接收端写“主角走进便利店，保持和上一镜头是同一个人”。匹配后，角色说明与参考图才进入生成输入。

## 判断与查看

- 只匹配当前接收端已连接的技能。普通上游剧本内容和技能正文不会替代接收端提示词触发匹配。
- 候选匹配只使用名称、用途、场景、排除条件和输入类型，不提前读取技能正文或图片。
- “不需要电影感”等明确否定，应使对应技能保持待命。无关、含糊或仅引用例子的表达也不应启用。
- 判断由现有文本模型完成，不是简单关键词搜索。画布展示启用列表、理由与提示词证据，可用于检查误选；调整用途或排除条件后再次运行。
- 虚线表示待命；启用后连线变为实线。修改提示词、用途、输入类型或连接关系后，显示待匹配。
- 展开“实际输入”查看该次运行保存的完整文本和实际参考图片。它是运行快照，之后编辑内容不会悄悄改变历史输入。

## 缓存和限制

- 提示词、候选元信息变化时重新判断；“强制重跑”也会重新判断。
- 已启用技能的正文与图片内容变化，会更新下一次生成输入。只修改待命技能正文，不会使普通生成重复运行。
- 同一参考文件通过多个技能连接时仅发送一次。一次发送最多 4 张、单张最多 10 MiB，合计最多 20 MiB；多个来源在接收端共同计数。
- 已启用技能的合并实际文本输入上限为 16 MiB，超出会在发送前明确拒绝，不静默截断；超过 2 MiB 的合法合并输入也能完整查看。
- 文本生成带图时，已配置模型需要支持图片输入；不支持时明确失败，不静默丢图。
- 技能用途不匹配时，缺失的参考文件或尚未运行的独占来源不影响普通生成。来源同时用于普通分支时，按普通分支规则执行。
- 匹配失败、非法选择、已启用技能为空或参考文件不可读取时，停止本次生成并显示具体原因。
- 需求判断会使用已配置文本模型；文本 / 图片生成继续使用已有设置。正常运行可能产生模型费用。

## 验证范围

本次采用本地替代模型接口、真实 ACP 子进程夹具和真实画布插件进行验证，没有调用付费模型。因此实际语义匹配准确率、当前账号的图片输入能力和远端参考图编辑服务还需在正常使用时确认。
