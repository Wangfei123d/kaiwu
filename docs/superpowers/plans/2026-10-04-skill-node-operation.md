# 开物技能节点实施记录

## 操作背景

用户批准将 HTML 方案接入 E:/project/kaiwu。技能接收文本与图片，连接后默认待命；接收端提示词只要表达相关需求，就自动选择对应技能，无需 @ 或固定引用语法。用户已选择直接修改当前目录，保留原有改动。

## 操作过程

1. 核对短剧节点类型、连线、拓扑执行、缓存、配置模型、IPC 和现有画布交互。
2. 建立元信息候选与语义匹配器，候选不含正文和文件路径；验证已连接 ID、需求证据和结构化返回，错误时停止生成。
3. 新增技能节点和图片输入节点；生成节点增加独立技能端口。执行时先排除技能边，识别需求后只恢复选中的技能及其来源。
4. 将技能全文、真实参考图字节、选择结果及内容指纹接入文本/画面生成；适配器继承当前设置、五分钟图片请求超时和不重试规则。
5. 接入技能名称/用途/场景/排除条件编辑、图片导入预览、逐条断开、待命虚线、启用理由和实际输入查看。
6. 隔离画布检查发现嵌套参考图库被生成图库尺寸规则影响；限定规则只作用于直接结果图库，并把边距纳入最小高度。复测参考图 145px、生成图库至少 88px。
7. 独立审查确认匹配和适配器正确，提出实际输入保存时机、长输入读取上限、共享图片重复发送三项问题；按行为测试先失败再修复。
8. 最终复验：全量 1984 项，1983 通过、1 跳过、0 失败；针对性 44/44 通过；隔离画布、语法、改动格式检查通过。最终独立复审确认三项问题全部关闭，无新 Critical/Important/Minor 发现。额外将待命来源断言明确改为故意会失败的 shell，复测仍 44/44。无真实模型调用，未改真实短剧项目数据，未提交、重置或清理 Git 改动。

## 涉及的知识点

- 按需依赖：连线表示“可使用”，并不代表每次都运行。先选中资料包，再读取其内容，避免不相关内容混入生成。
- 语义识别：模型判断用户真正想做什么，覆盖不同说法；结果仍需验证与展示，不能假装匹配永远准确。
- 多模态传递：图片必须发送真实图片数据，只有文件名或路径不能让模型看见图。
- 内容指纹：用文字和图片内容计算标识，资料变化才让相关生成更新，减少重复请求。
- 运行快照：把发送时的内容保存下来，之后编辑不改变历史记录，失败时也能追查。
- 多层校验：界面和主进程都验证格式、大小和目录范围；主进程做最终判断，不能只相信界面输入。

## 分析过程

“连接后全部拼接”会违背默认待命规则，“必须 @”又不符合自然表达需求。最终把选择阶段与读取阶段拆开：选择阶段只看用途等元信息，之后才执行必要来源并生成实际输入。

固定关键词无法覆盖“同一个人”“前后长相一致”等表达，因此沿用配置文本模型做语义判断，并用连接范围、原文证据、排除条件和明确失败来控制误选风险。缓存复用匹配结果，提示词或用途变化才重识别。

## 注意事项

- 实际语义准确率与远端参考图编辑服务没有进行付费验证；正常使用时查看启用理由。
- 文本模型带图时需要支持图片输入；缺失能力会报错，不会默默丢掉参考图。
- 图片限额为单张 10 MiB、合计 20 MiB、每次最多 4 张，接收端共同计数；相同项目参考文件重复连接只发送一次。
- 合并的技能实际文本输入上限为 16 MiB，正常生成结果仍为 2 MiB；超限明确拒绝，不截断。
- 重启开物后主进程与画布将加载更新代码。
- 因本任务写入范围限于已授权项目，本操作记录保存于项目文档目录，不写入外部默认报告目录。
