# 文本/剧本节点正文区高度自适应

## 操作背景

用户截图显示：节点框已经拉高，但文本/剧本正文仍集中在顶部，下面留有大量空白。直接修复现有项目，不新增交互方案。

## 排查与操作过程

1. 检查 `plugins/drama/index.js` 和 `style.css`。文本节点沿用通用 `.drama-out`：正文仅截取运行缓存的前 120 字，最高 42px；阅读、编辑区均未采用填满节点的弹性布局。
2. 新增 `tools/check-text-node-layout.cjs`，使用真实画布插件与本地夹具。修复前测试失败：300px 节点只有 42px 正文区，复现截图现象。
3. 为文本节点添加专用弹性布局。阅读区显示当前完整正文；编辑框占用节点剩余空间；内容太长时内部滚动。保留换行与纯文本显示，不加入新 Markdown 交互。
4. 最小节点高度仅计标题、说明栏和最小正文空间，排除弹性正文的 `scrollHeight`，避免只能拉高不能缩小。普通滚动不平移画布，Ctrl+滚轮仍用于画布缩放；正文可选择复制。
5. 检查最小高度的导入流程，新增测试复现确认条与 textarea 重叠。确认条出现/移除时重算最小高度，测试转为通过。
6. 保留默认紧凑高度，已保存的自定义高度优先；测试未运行节点也能显示正文，编辑后不会被旧缓存覆盖。

## 涉及的知识点

- 弹性布局：标题占固定位置，正文使用剩余空间。外框拉高，内部框随之变高。
- 内部滚动：正文可以很多，但不必把节点无限撑大；用滚动条查看其余内容。
- 最小高度：不能把“当前已经伸展的正文高度”作为缩小的下限，否则拉高后缩不回去。
- 当前内容与缓存：缓存描述上一次运行，不应替代正在编辑的正文。
- 测试驱动：先让真实界面测试失败，再修复，再验证通过，避免只看代码推测效果。
