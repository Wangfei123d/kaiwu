# AI 回复缓冲显示修复

用户已明确要求：流式内容先暂存；更快逐字显示；缓存不足时放缓；扫光只照亮已经显示的文字；实时渲染 Markdown。沿用本次明确的行为规格，直接在当前工作树实施。

## 实施方案

1. 增加独立的回复播放器。完整接收文本只存于内存，按帧推进显示游标；大积压快速消耗，小积压按输入速度放缓。流式结束后继续消耗缓存，不重播已经显示的内容。
2. 每帧只将游标之前的文本交给现有安全 Markdown 渲染器。用节点协调保留已显示结构、代码滚动位置和图片；新文字短暂提亮。扫光层与正文使用完全相同的已显示内容，扫光容器保持稳定。
3. 面板按消息 ID 保留播放器，结构重绘与 prompt-end 不重置游标；切换会话、清空和卸载时回收帧任务。历史消息直接显示。
4. 回归检查：未显示正文不在 DOM；结束事件不跳出全文；低速输入时扫光持续；实时 Markdown；Unicode 与长回复完整；会话清理无残留。检查完成后按用户既有要求重启开物。
