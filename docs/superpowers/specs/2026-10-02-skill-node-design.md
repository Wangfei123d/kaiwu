# 技能节点设计草案

状态：2026-10-04 已实现并通过最终复审、全量本地测试和隔离画布验证。真实模型语义准确率与远端参考图服务未做付费验证。

## 节点和连线

技能节点是按需读取的资料包，接收文本和图片两种类型，支持多个同类型输入。节点使用唯一 ID 标识，名称可编辑；用途描述和技能输出端口用于自然语言匹配。用户不需要填写唯一调用别名。普通节点内容继续按现有规则输入；技能端口单独登记可用技能，不直接并入普通提示词。

技能与接收端连接后默认待命。接收端运行前识别提示词中的实际需求，匹配已连接技能的用途，只读取符合本次需求的技能。未选中技能的上游来源不因这条连线被执行、读取或下载。其他活跃分支独立使用同一个来源时不受影响。技能自身不执行额外生成调用；自动匹配阶段需要使用已配置文本模型识别需求。

## 触发方案

用户最新要求：无需写 `@`、技能名称或固定声明，只要提示词表达相关需求，就启用对应技能。例如“保持主角和上一镜头是同一个人”启用人物一致性；“光影像胶片电影一样”启用电影光影。旧的引用标签和声明式指令是前一版备选，不再是使用技能的前提。

正式版本采用语义匹配，而非仅靠固定关键词。匹配阶段只读取候选技能的 ID、名称、用途描述、适用场景、排除条件、输入类型摘要，不读取技能文本正文和图片。根据接收端当前提示词与元信息生成结构化选择结果，包含选中的技能 ID、提示词中的对应需求及理由。验证所有 ID 必须属于已连接候选范围，不能由模型编造节点或获取未连接资料。

明确否定优先，例如“保持人物一致，不需要电影感”只启用人物一致性。引用词语作为例子或出现技能名称不等同于实际需求。没有相关需求、语义不明确时保持待命；匹配服务失败时提示匹配失败并停止本次生成，不能假装已识别。多个技能可以同时匹配，同一个技能只读取一次，按连入顺序稳定拼装。普通上游剧本/资料内容不能反向触发技能，技能正文中提到其他技能也不递归触发。

## 运行数据和显示

需求匹配和来源读取结束、提交生成请求之前，保存并显示本次实际输入预览：普通提示词、普通节点内容、已启用技能的完整文本、技能参考图片。提示词保持用户自然语言原文。画布展示匹配理由、已启用技能及保持待命的技能。失败后保留已提交输入的记录。用户不需要手动填写技能声明。

技能文本保持完整，不静默截断。合并后的实际文本输入设置 16 MiB 安全上限，超出时在发送前明确拒绝；正常生成结果仍沿用原先 2 MiB 上限。图片作为真实图片或参考图发送给支持图片输入的接收模型，不能仅把文件路径拼进提示词。使用图片时若接收端模型/接口不支持图片输入，运行前明确提示并阻止提交，不静默丢弃图片。无参考图仍使用 images/generations；有参考图使用 images/edits multipart。文本生成通过既有 ACP 图片能力发送实际图像。

已有连线显示待命虚线；本次启用显示实线和“本次启用”。单个技能可显示各输入来源，并逐条断开。缓存指纹纳入当前提示词、匹配器版本、候选技能元信息、匹配结果、本次启用的技能顺序、文本内容和图片内容指纹。仅未启用技能正文的变化不会改变接收端缓存；用途元信息变化可能影响匹配，需要重新识别。

## 异常和边界

匹配结果越出候选范围、启用技能内容全部为空、图片文件缺失/不可读取、接收端不支持图片时，提示具体问题并阻止生成调用。未启用时，技能的内容缺失不阻止普通接收端运行。技能输入允许文本、文本生成结果、图片输入或已有画面结果；技能之间先不支持级联。
