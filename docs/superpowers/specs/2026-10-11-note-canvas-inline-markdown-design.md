# 笔记画布节点内 Markdown 编辑设计

## 目标

笔记画布中的 Markdown 内容可直接在原节点内编辑，并在编辑时保留 Markdown 的格式化呈现；双击节点不再打开独立编辑面板。

## 范围与交互

- Markdown 文本节点始终以可编辑的富文本表面显示。标题、列表、引用、粗体等格式在节点内实时呈现；工具栏和保存状态也留在节点中。
- `.md` 文件引用节点使用同一套节点内编辑表面。节点内的保存操作将 Markdown 写回原文件，并沿用当前的版本/内容冲突检查；失败时保留草稿并显示错误，不静默覆盖。检测到外部修改冲突时，节点提供「重载原文」操作，并在丢弃草稿前二次确认。
- `.txt` 文件引用保持纯文本显示，仍使用原有的纯文本编辑流程。
- 编辑不应被画布拖动、框选、快捷键删除或节点内部滚动误触。用户在文本编辑区输入时，焦点和选择范围保持稳定。
- 文件节点只在 Markdown 文件载入完成且允许写入后启用编辑；只读文件显示原有原因并禁止保存。

## 实现边界

复用 `app/lib/live-markdown.js` 的安全渲染和 DOM 到 Markdown 序列化能力，在 `plugins/note-canvas/canvas-view.js` 中直接挂载到节点正文。文本节点输入更新画布会话；`.md` 引用节点维护局部草稿，并通过已有 `readNote` / `writeNote` 接口和 revision 机制保存。节点重绘、画布切换与插件卸载时，不得丢弃未保存文件草稿；至少应保留或明确提示。

样式局限在笔记画布节点，节点宽高变化时编辑内容仍可滚动并正确换行。普通笔记编辑器的行为不在本次变更范围；`.txt` 不启用 Markdown。

## 验收标准

1. 双击 Markdown 文本节点正文或标题不会打开遮罩层/独立编辑面板；正文原位可输入。
2. 输入 Markdown 内容后，格式化结构在同一节点实时显示，保存值可序列化回 Markdown。
3. 文本节点修改保存到画布图数据。
4. `.md` 文件节点能在节点内编辑并写回原文件；外部修改冲突不会被覆盖，草稿保留并给出可见错误；用户确认「重载原文」后能读取最新磁盘内容。
5. `.txt` 节点仍按纯文本呈现并保持原有编辑行为。
6. 进入正文输入状态时，节点拖拽/删除/画布快捷键不会抢走输入；退出编辑后节点常规拖动仍可用。
