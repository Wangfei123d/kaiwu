# 开物首选项菜单设计规格

## 背景

当前外壳顶部有“笔记”和“设置”两个主视图标签。“设置”会打开一个完整设置页，页面内含搜索框、四个分区（AI 与 Agent、界面、服务、笔记库）以及 11 项设置。用户希望移除顶部“设置”标签，并从“编辑”原生菜单进入设置。

## 用户目标

- 顶部主视图导航只保留“笔记”，移除截图中的“设置”标签。
- “编辑”菜单中提供一个“首选项…”入口。
- 点击该入口打开现有完整设置页，不复制或拆分设置表单。

## 设计

### 菜单

在原生“编辑”菜单现有撤销、剪切、复制、粘贴、全选等命令后添加分隔线，再添加单一菜单项“首选项…”。点击它通过 Electron 主进程和 preload 的受限桥接通知渲染层打开设置视图。该项不携带路径、设置值或可执行对象，也不增加快捷键。

### 主界面

删除 `app/index.html` 中的 `viewSettings` 按钮；保留 `paneSettings` 及其样式、设置视图模块和全部设置数据。外壳仍从笔记视图启动，接收到首选项事件后复用现有 `switchView('settings')`，保持现有设置页的搜索、四分区导航、读数刷新和写入行为。

顶部仍保留“笔记”作为返回入口。由于它不再是成对的页签，主导航移除 `tablist` / `tab` 语义，按钮通过 `aria-current="page"` 表示笔记视图当前活动；进入首选项时清除该属性，返回笔记时恢复。不得额外增加顶部按钮、侧栏或新窗口。工作台布局及笔记、插件面板不受影响。

### IPC 与安全边界

- `electron/app-menu.js` 继续作为纯菜单模板；新增一个首选项点击回调参数。
- `electron/main.js` 只向当前主窗口发送固定通道 `menu:open-preferences`，不转发菜单对象或任意输入。
- `electron/preload.cjs` 通过现有闭包桥暴露 `onOpenPreferences(callback)`：必须校验 callback 是函数，收到的回调不带 Electron event 或其他参数，并返回取消订阅函数。
- `app/main.js` 订阅事件并调用既有设置视图切换逻辑。

### 测试

- 原生菜单模板单测断言“首选项…”位于“编辑”菜单、排序在标准编辑命令之后，点击只调用指定回调；其他编辑命令及 Windows/macOS 菜单结构保持不变。
- shell 合同测试断言 `viewSettings` 顶部入口已移除、设置面板仍保留、单一“笔记”入口语义有效，并且首选项事件接回现有设置切换。
- preload 测试验证回调类型检查、无 Electron event 参数和取消订阅行为。
- 更新设置常量测试，移除已失效的 `SETTINGS_VIEW.tabId` 契约；更新 Electron 自测，使其通过共同的偏好页入口打开设置，而不再点击不存在的按钮。
- 运行相关定向测试、全量 `npm test`，再运行 Electron 自测并记录不相关的既有失败。

## 非目标

- 不把 11 个控件拆成单独的原生菜单命令；菜单仅有一个“首选项…”入口。
- 不创建独立设置窗口，不修改任何设置 ID、存储命名空间、值、IPC 设置通道或生效时机。
- 不调整“笔记”视图、工作台布局、插件工具菜单和现有设置页视觉布局。

## 验收标准

1. 顶部不存在“设置”主视图标签；“笔记”入口仍能返回笔记视图，且没有单成员 tablist。
2. “编辑 → 首选项…”可打开完整现有设置页。
3. 设置项仍可搜索、浏览、读写，既有设置数据保持不变。
4. 菜单回调通过受限 preload 通道传递，不暴露 Electron event 或设置数据。
5. 原生菜单、shell、preload 和设置常量的自动化测试通过。
