# DOCX 内置阅读器设计

## 目标

在开物中点击笔记树里的 `.docx` 文档时，于开物主窗口的标签页内只读预览文档。保留原文件，不把阅读操作写回 DOCX，也不转交给系统默认应用。

## 用户界面

- 采用开物现有深色界面和标签页模式；文档标签显示文件名及“只读”状态。
- 提供文档目录导航、正文搜索、缩放和页面导航。
- 阅读区域呈现分页纸张布局，支持标题、段落、列表、表格和常见图片等内容。
- 对于不支持、损坏或受密码保护的文档，在阅读区域显示清楚的错误说明和返回入口。

HTML 交互稿位于 `docs/previews/docx-reader-preview.html`。它是静态提案，不负责解析或加载真实 DOCX 文件。

## 打开与数据流

1. 用户从笔记树打开 `.docx` 文件，开物沿用现有笔记库内文件路径校验。
2. 主进程读取所选文件并在本机解析，不上传文档内容。
3. 渲染层接收经过净化的只读文档表示，在内部标签中排版。
4. 从标题生成目录；搜索和缩放在阅读视图中执行，不修改源文件。

具体解析库及其打包策略留待实现计划阶段，需优先确认本地运行、许可和 Electron 安全边界。

## 范围与安全

- 第一阶段仅支持只读浏览，不支持编辑、回存、导出或打印。
- 保持源 DOCX 字节不变；不允许文档 HTML 执行脚本或加载不必要的远程资源。
- 搜索仅在当前已解析文档内进行。
- 无法解析时保留用户在开物中的工作状态，并提供可理解的失败提示。

## 验收标准

- 从笔记树打开 DOCX 后显示在开物内部阅读标签，而不是系统外部程序。
- 目录项可跳转，搜索结果可定位，缩放可调整阅读字号/页面比例。
- 原文件打开前后保持不变。
- 普通 DOCX、损坏/加密文件和不支持内容都有明确且安全的处理结果。
- 普通笔记及既有文件打开行为不受影响。

## 验证方向

实现时应使用代表性的 DOCX 样例覆盖标题层级、表格、图片、长文档和异常文件，并检查阅读视图与现有标签交互。本设计阶段不包含真实文件解析或应用功能实现。
